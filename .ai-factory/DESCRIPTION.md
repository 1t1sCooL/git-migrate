# git-migrate — двусторонняя миграция git-зеркал

## Обзор

CLI-утилита на Node.js для зеркальной миграции репозиториев между GitLab и GitHub в обоих направлениях (`GitLab → GitHub` и `GitHub → GitLab`). Направление выбирается интерактивно в терминале или задаётся через переменную `MIGRATION_DIRECTION`. Все создаваемые на стороне назначения репозитории/проекты создаются как `private`. По умолчанию имя репозитория сохраняется как в источнике.

## Основные возможности

- Выбор направления миграции: интерактивно или через `MIGRATION_DIRECTION`
- Получение списка репозиториев источника через REST API (GitLab/GitHub) с пагинацией
- Автоматическое создание репозитория/проекта на стороне назначения, если он отсутствует
- Сохранение исходного имени репозитория (настраивается через `USE_ORIGINAL_REPO_NAME`)
- Для `GitHub → GitLab` — автоматическое создание целевой подгруппы по owner из GitHub (`PRESERVE_SOURCE_OWNER_AS_GITLAB_GROUP`)
- Зеркальный перенос истории: `git clone --mirror` / `git fetch --prune` из источника и `git push --mirror` в назначение
- Опциональный перенос LFS-объектов (`MIGRATE_LFS`)
- Безопасный прогон без изменений (`DRY_RUN`)
- Поддержка приватных GitLab-инстансов через `GITLAB_BASE_URL`

## Технологический стек

- **Язык программирования:** JavaScript (Node.js 18+, CommonJS)
- **Фреймворк:** отсутствует (standalone CLI-скрипт)
- **База данных:** отсутствует
- **ORM:** отсутствует
- **Зависимости:** только встроенные модули Node (`fs`, `path`, `child_process`, `readline`, `process`) + внешний бинарь `git` в PATH
- **Интеграции:** GitLab REST API, GitHub REST API
- **Тесты:** встроенный `node:test` (`make test`, входит в `make ci`)

## Архитектурные заметки

- Один исполняемый файл `git-migrate.js` (~718 строк), организованный функционально без классов
- Конфигурация целиком формируется из переменных окружения (загружаются из `.env` при старте): поведенческие флаги в `config`, удалённые стороны — в четырёх профилях (`sourceGitlab`, `sourceGithub`, `destGitlab`, `destGithub`) с переменными `SOURCE_*`/`DEST_*` и fallback на легаси `GITLAB_*`/`GITHUB_*`
- Логирование с уровнями через `LOG_LEVEL` (debug|info|warn|error); креденшалы в URL редактируются перед выводом
- Слои: загрузка/валидация конфигурации → HTTP-клиенты к API → git-операции через `spawn` → функции миграции по направлениям → `main()` как оркестратор
- Пакетная обработка: ошибка по одному репозиторию не останавливает миграцию остальных, итог отражается в коде выхода

## Нефункциональные требования

- Логирование: информационные сообщения через `log()`/`console.log`, ошибки через `console.error`
- Обработка ошибок: проверка обязательных env на старте, изоляция ошибок отдельных репозиториев, ненулевой код выхода при сбоях
- Безопасность: токены только из окружения/`.env` (в `.gitignore`); все целевые репозитории создаются приватными; режим `DRY_RUN` для безопасной проверки
