# Базовые правила проекта

> Автоопределённые соглашения на основе анализа кодовой базы. Редактируйте по необходимости.

## Соглашения по именованию

- Файлы: kebab-case (`git-migrate.js`)
- Переменные: camelCase; константы уровня модуля — UPPER_SNAKE_CASE (`REQUIRED_ENV`)
- Функции: camelCase (`migrateGitLabToGitHub`, `ensureGitHubRepo`)
- Классы: не используются (функциональный стиль)
- Асинхронные функции: префиксов нет, помечаются ключевым словом `async`

## Структура модулей

- Один исполняемый CommonJS-файл `git-migrate.js` с shebang `#!/usr/bin/env node`
- Модули подключаются через `require("node:...")` (только встроенные модули Node, без внешних зависимостей)
- Конфигурация собирается в единый объект `config` из переменных окружения
- Логическое разделение по функциям: загрузка env, HTTP-клиенты (GitLab/GitHub API), git-операции (clone/fetch/push --mirror), функции миграции по направлениям, `main()` как точка входа

## Обработка ошибок

- Проверка обязательных переменных окружения на старте: `console.error` + `process.exit(1)`
- Прикладные ошибки — через `try/catch`; для пакетной обработки репозиториев ошибка одного не останавливает остальные, считается счётчик `failed`
- Ненулевой код выхода при наличии ошибок: `process.exitCode = 1` / `process.exit(1)`

## Логирование

- Информационные сообщения: helper `log(message)` поверх `console.log`
- Ошибки: `console.error`
- Поддержка режима `DRY_RUN` для безопасного прогона без реальных изменений

## Прочее

- Внешние процессы (git) запускаются через `child_process.spawn`, обёрнутый в `run(cmd, args)`
- Секреты (токены GitLab/GitHub) читаются только из окружения/`.env`, в код не хардкодятся; `.env` в `.gitignore`
