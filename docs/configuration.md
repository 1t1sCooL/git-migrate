# Конфигурация

Все настройки задаются через переменные окружения (загружаются из `.env` при старте). Эталон — `.env.example`.

## Профили источника и назначений

Удалённые стороны описываются четырьмя профилями. Новые переменные `SOURCE_*`/`DEST_*` имеют приоритет; если они не заданы, используются легаси-переменные `GITLAB_*`/`GITHUB_*` (они заполняют обе стороны сразу).

### Источник: GitLab (например, рабочий инстанс)

| Переменная | Легаси-fallback | Описание |
|------------|-----------------|----------|
| `SOURCE_GITLAB_BASE_URL` | `GITLAB_BASE_URL` | Базовый URL GitLab-источника. Завершающие слэши обрезаются. |
| `SOURCE_GITLAB_TOKEN` | `GITLAB_TOKEN` | Токен с правами на чтение репозиториев источника. |
| `SOURCE_GITLAB_GROUP_ID` | `GITLAB_GROUP_ID` | Группа-источник. Если пусто — берутся все доступные токену репозитории (`membership=true`). |

### Источник: GitHub (для направления GitHub → GitLab)

| Переменная | Легаси-fallback | Описание |
|------------|-----------------|----------|
| `SOURCE_GITHUB_TOKEN` | `GITHUB_TOKEN` | Токен с правами на чтение. |
| `SOURCE_GITHUB_OWNER` | `GITHUB_OWNER` | Владелец-источник (user или org). |
| `SOURCE_GITHUB_OWNER_TYPE` | `GITHUB_OWNER_TYPE` | `user` или `org` (по умолчанию `user`). |

### Назначение: GitLab (например, личный)

| Переменная | Легаси-fallback | Описание |
|------------|-----------------|----------|
| `DEST_GITLAB_BASE_URL` | `GITLAB_BASE_URL` | Базовый URL GitLab-назначения. |
| `DEST_GITLAB_TOKEN` | `GITLAB_TOKEN` | Токен с правами на создание проектов/групп. |
| `DEST_GITLAB_NAMESPACE_ID` | `GITLAB_TARGET_NAMESPACE_ID` | Namespace назначения. Если пусто — личный namespace токена. |

### Назначение: GitHub (например, личный)

| Переменная | Легаси-fallback | Описание |
|------------|-----------------|----------|
| `DEST_GITHUB_TOKEN` | `GITHUB_TOKEN` | Токен с правами на создание репозиториев. |
| `DEST_GITHUB_OWNER` | `GITHUB_OWNER` | Владелец-назначение. |
| `DEST_GITHUB_OWNER_TYPE` | `GITHUB_OWNER_TYPE` | `user` или `org` (по умолчанию `user`). |

> Валидация выполняется по выбранному направлению: `gitlab-to-github` требует заполненные sourceGitlab и destGithub, `github-to-gitlab` — sourceGithub и destGitlab. При нехватке скрипт перечисляет недостающие переменные (включая легаси-эквиваленты) и завершается с ошибкой.

## Направление миграции

| Переменная | Значения | По умолчанию |
|------------|----------|--------------|
| `MIGRATION_DIRECTION` | `gitlab-to-github` или `github-to-gitlab` (также принимаются `1`/`2`, `gl2gh`/`gh2gl` и синонимы) | пусто → скрипт спросит интерактивно |

## Именование репозиториев

| Переменная | Значения | По умолчанию |
|------------|----------|--------------|
| `USE_ORIGINAL_REPO_NAME` | `true` — сохранять имя как в источнике; `false` — старая схема со склейкой namespace. | `true` |
| `PRESERVE_NAMESPACE_IN_NAME` | Сохранять namespace в имени репозитория. | `false` (в `.env.example`); `true` в коде, если переменная не задана |
| `PRESERVE_SOURCE_OWNER_AS_GITLAB_GROUP` | Для `GitHub → GitLab`: создавать/использовать подгруппу с именем owner из GitHub и создавать репозиторий внутри неё. | `true` |

## Поведение и флаги

| Переменная | Значения | По умолчанию | Описание |
|------------|----------|--------------|----------|
| `INCLUDE_ARCHIVED` | `true`/`false` | `false` | Включать архивные репозитории источника. |
| `INTERACTIVE_NAMING` | `true`/`false` | `true` | Если репозитория ещё нет в назначении — спросить имя в терминале (Enter — имя по умолчанию). При `false` или запуске без TTY (cron, CI) используется имя по умолчанию без вопросов. Не действует при `DRY_RUN=true`. |
| `MIGRATE_LFS` | `true`/`false` | `false` | Дополнительно переносить LFS-объекты (требует git-lfs). |
| `DRY_RUN` | `true`/`false` | `true` | Безопасный прогон без реальных изменений. |
| `MIRROR_ROOT` | путь | `./mirrors` | Локальная директория для зеркальных клонов. |
| `LOG_LEVEL` | `debug`/`info`/`warn`/`error` | `info` | Уровень логирования. `debug` трассирует API-вызовы и git-команды; креденшалы в URL маскируются. |

## Замечания

- Все создаваемые на стороне назначения репозитории/проекты создаются как `private`.
- Токены не хардкодятся в коде — только через окружение. Файл `.env` добавлен в `.gitignore`.
- Директория зеркал (`mirrors/`), логи и отчёты также игнорируются git.
