# Конфигурация

Все настройки задаются через переменные окружения (загружаются из `.env` при старте). Эталон — `.env.example`.

## Обязательные переменные

| Переменная | Описание |
|------------|----------|
| `GITLAB_BASE_URL` | Базовый URL GitLab (например `https://gitlab.com` или адрес self-hosted инстанса). Завершающие слэши обрезаются. |
| `GITLAB_TOKEN` | Токен GitLab с правами на чтение источника и/или создание проектов. |
| `GITHUB_TOKEN` | Токен GitHub (PAT) с правами на чтение источника и/или создание репозиториев. |
| `GITHUB_OWNER` | Владелец на стороне GitHub: имя пользователя или организации. |

> Если любая из обязательных переменных не задана, скрипт выводит `Missing required env var: ...` и завершается с кодом 1.

## Направление миграции

| Переменная | Значения | По умолчанию |
|------------|----------|--------------|
| `MIGRATION_DIRECTION` | `gitlab-to-github` или `github-to-gitlab` (также принимаются `1`/`2`, `gl2gh`/`gh2gl` и синонимы) | пусто → скрипт спросит интерактивно |

## GitHub: настройки владельца

| Переменная | Значения | По умолчанию |
|------------|----------|--------------|
| `GITHUB_OWNER_TYPE` | `user` (личный аккаунт) или `org` (организация) | `user` |

## GitLab: источник и назначение

| Переменная | Описание | По умолчанию |
|------------|----------|--------------|
| `GITLAB_GROUP_ID` | Группа-источник при `GitLab → GitHub`. | пусто |
| `GITLAB_TARGET_NAMESPACE_ID` | Namespace назначения при `GitHub → GitLab`. Если пусто — проект создаётся в личном namespace токена GitLab. | пусто |

## Именование репозиториев

| Переменная | Значения | По умолчанию |
|------------|----------|--------------|
| `USE_ORIGINAL_REPO_NAME` | `true` — сохранять имя как в источнике; `false` — старая схема со склейкой namespace. | `true` |
| `PRESERVE_NAMESPACE_IN_NAME` | Сохранять namespace в имени репозитория. | `false` (в `.env.example`); `true` в коде, если переменная не задана |
| `PRESERVE_SOURCE_OWNER_AS_GITLAB_GROUP` | Для `GitHub → GitLab`: создавать/использовать подгруппу с именем owner из GitHub и создавать репозиторий внутри неё. | `true` |

## Поведение и флаги

| Переменная | Значения | По умолчанию | Описание |
|------------|----------|--------------|----------|
| `INCLUDE_ARCHIVED` | `true`/`false` | `false` | Включать архивные репозитории источника. |
| `INTERACTIVE_NAMING` | `true`/`false` | `true` | Если репозитория ещё нет в назначении — спросить имя в терминале (Enter — имя по умолчанию). При `false` или запуске без TTY (cron, CI) используется имя по умолчанию без вопросов. Не действует при `DRY_RUN=true`. |
| `MIGRATE_LFS` | `true`/`false` | `false` | Дополнительно переносить LFS-объекты (требует git-lfs). |
| `DRY_RUN` | `true`/`false` | `true` | Безопасный прогон без реальных изменений. |
| `MIRROR_ROOT` | путь | `./mirrors` | Локальная директория для зеркальных клонов. |

## Замечания

- Все создаваемые на стороне назначения репозитории/проекты создаются как `private`.
- Токены не хардкодятся в коде — только через окружение. Файл `.env` добавлен в `.gitignore`.
- Директория зеркал (`mirrors/`), логи и отчёты также игнорируются git.
