# Начало работы

Установка, настройка окружения и первый запуск миграции git-зеркал.

## Требования

| Компонент | Версия / условие |
|-----------|------------------|
| Node.js | 18+ |
| git | в `PATH` |
| git-lfs | только при `MIGRATE_LFS=true` |
| Токен GitLab | с правами на чтение источника / создание проектов |
| Токен GitHub | с правами на чтение источника / создание репозиториев |

## Установка

Внешних зависимостей нет — скрипт использует только встроенные модули Node.

```bash
git clone https://github.com/1t1sCooL/git-migrate
cd git-migrate
```

## Настройка окружения

1. Скопируйте шаблон окружения:

   ```bash
   cp .env.example .env
   ```

2. Заполните значения в `.env` (токены, владельцы, направление, флаги). Полное описание всех переменных — в [Configuration](configuration.md).
3. Скрипт автоматически загружает `.env` при старте.

Обязательные переменные: `GITLAB_BASE_URL`, `GITLAB_TOKEN`, `GITHUB_TOKEN`, `GITHUB_OWNER`. Если хотя бы одна не задана, скрипт завершится с ошибкой.

## Первый запуск

Рекомендуется начинать с безопасного прогона `DRY_RUN=true` (значение по умолчанию в `.env.example`):

```bash
node git-migrate.js
```

Скрипт спросит направление миграции в терминале (если не задано `MIGRATION_DIRECTION`). В режиме `DRY_RUN` реальные изменения не выполняются — вы видите, что было бы сделано.

## Проверка результата

- В выводе перечисляются обрабатываемые репозитории и действия по каждому.
- При наличии ошибок по отдельным репозиториям миграция продолжается, а итоговый код выхода будет ненулевым.
- Когда прогон выглядит корректно — выставьте `DRY_RUN=false` и запустите повторно для реальной миграции.
